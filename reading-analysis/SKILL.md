# 分析阅读

## 目标与边界

默认目标是忠实理解作者：对一份可读材料或指定部分进行**重构**，不以摘抄或评价代替理解。材料必须由用户提供或明确授权读取；不得检索、下载、导出、修改或保存材料。只有用户明确要求评价、反驳、核验或比较时，才在重构完成后增加 `评议`。

阅读 [workflow.md](references/workflow.md) 以执行完整流程。只在需要细化步骤时加载它；本文件保留必要边界。

## 先确定范围与类型

1. 声明可访问材料、已读/未读范围与稳定定位方式。片段只能支撑局部结论。
2. 将材料暂定为 `知识类`、`文学类` 或混合；说明依据，分类不确定时请求用户修正。
3. 用户未给目标时，优先理解作者提出的问题、整体结构及表达方式；不自动交接到其他阅读 Skill。

## 两条重构路径

### 知识类

依次交付：材料类别与受众、全貌概述、结构纲要、作者试图回答的问题、关键术语、主要主张、论证或证据链、已经解决与仍未解决的问题。对争议或缺口保持可核验的定位，不补造作者未说出的论点。

### 文学类

依次交付：整体结构、叙述视角或人物关系、主题推进、意象与语言/形式、阅读体验及不确定之处。文学材料不强迫套入“作者问题—命题—论证”的链条；解释应与文本定位和表达选择相连。

## 有内容的层级摘要与思维导图

完成上述重构后，材料具有可见层级时增加“层级摘要”和“层级思维导图”。完整书籍可压缩到全书、部分、章和关键节；指定章节或片段只画实际可读的层级，并声明未读范围。摘要只压缩已读节点，不预测未读内容。详细做法见 [workflow.md](references/workflow.md#3-有内容的层级摘要与思维导图)。

层级摘要不是目录、章节标题的改写，也不是把每节的细节堆在一起。每个节点须用自己的话说明：作者在此**提出、解释、证明、转折或推进了什么**，以及它怎样服务父节点；必要时补一个决定理解的机制、条件或证据类型。标题只用作定位，不能充当摘要。每个节点附稳定定位和 `原文陈述`、`AI 推断` 或 `待核验问题` 标签。

导图根节点是“书名／本次范围”，父子关系必须与紧邻的层级摘要一致，而不是围绕用户问题另起一张图。标题级别不可靠时，只能用目录、显式的部分/章/节命名或正文结构来判断父子关系，并在不确定处标为 `待核验问题`。默认先输出可读、可追溯的 Markdown 层级摘要，再用紧凑的 Mermaid `flowchart` 展示全貌；仅当用户明确偏好时使用 Mermaid `mindmap`。节点过多时合并同层细节，但不跳过层级或把标题当内容。需要可交互、适合展示的成品时，按工作流生成自包含 HTML 预览；无可见层级时说明限制，不伪造树状结构。

## 证据账本与可选评议

每个关键点附章、节、页码、段落标题或其他稳定定位，并明确标为：

- `原文陈述`：材料明示的内容或可直接定位的表达。
- `AI 推断`：基于材料的结构归纳、解释或暂定关系。
- `待核验问题`：范围缺失、歧义、冲突或需要更多材料之处。

只有用户明确提出时才增加 **评议** 区块，并且它必须位于完整重构之后。评议要说明采用的标准；外部资料须先获授权、单列来源，绝不混成原书证据。

## 质量检查

- 是否先说明范围，再按知识类或文学类路径重构？
- 是否在完整重构后，按实际可读范围输出层级摘要和与之同构的思维导图，而未预测未读内容？
- 删除章节标题后，每个摘要节点是否仍能让未读材料的人理解“作者说了什么、为何在这里说”？若不能，则重写，不以标题替代摘要。
- 父节点是否由子节点压缩而来，并说明其推进关系，而非把目录逐级复制？
- 每项主张、解释和空白是否有三类标签与定位？
- 评议是否为用户请求、晚于重构，且与外部信息严格分开？
- 是否没有因为材料不完整而假装完成全书分析？
