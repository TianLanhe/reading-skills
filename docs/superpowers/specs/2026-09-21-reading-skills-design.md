# 阅读辅助 Skills 设计

## 目标与边界

新增三个可自动发现的个人阅读辅助 Skill：`reading-inspection`、`reading-analysis` 与 `reading-synthesis`。它们帮助用户以可追溯的方式完成检视阅读、分析阅读和主题阅读；它们不是资料抓取、整书导出、外部检索或笔记同步工具。

共同边界：

- 原文优先。只有用户提供或明确授权读取的材料才能支撑书籍结论。书名、简介、截图或片段只能支撑阅读计划或局部结论。
- 关键结论标为“原文陈述”“AI 推断”或“待核验问题”，并保留章、节或其他稳定定位。
- 默认不检索、不下载、不修改材料，也不写入本地或外部服务；用户明确要求时才保存一份独立产物，且不覆盖同名内容。
- 知识类与文学类使用不同分析框架。无法可靠分类时，说明判断依据并请用户修正。
- AI 不自动串联三个 Skill；每个 Skill 只交付自己的阶段成果，并建议下一步。

## 三个 Skill

### `reading-inspection`

适用于用户想判断一份已可读材料是否值得投入时间、应该读到什么深度或如何开始阅读时。

它在有限范围内读取标题、前言、目录、索引（若有）、关键章节、摘要/结尾，输出材料类型、整体问题或主题、架构、可能的价值与局限、建议阅读层级和路径。它不假装完成精读，也不对思想真实性下结论。没有阅读目标时，默认回答“值得读吗、为何、下一步读什么”。

### `reading-analysis`

适用于用户要理解某一份已可读材料或指定章节的结构、主张、论证或文学表达时。

对知识类材料，依次重构类别、全书概述、结构、作者的问题、关键术语、关键主张、论证、已解与未解问题。对文学类材料，改为结构、叙述/人物、主题、意象或情感体验，不强行编造论证链。没有目标时，默认目标为理解作者的问题、主张与论证。

默认止于忠实理解。仅当用户明确要求评估、反驳、核验或比较时，才启用独立的评议区块；该区块必须在完整重构之后，并继续区分原文、推断和外部证据。

### `reading-synthesis`

适用于用户提出一个明确问题，并要比较至少两份已可读材料时。没有问题时必须先请求问题，不能替用户发明研究主题。

它先记录候选材料的纳入、排除与缺失状态，再从相关章节建立中立词汇、可由多数材料回应的问题、主要与次要争议，以及有出处的综合讨论。材料服务于用户问题；不得用任一作者的术语或结论支配比较框架。混合文学与知识类材料时，必须先声明比较维度及两类材料的不同证据地位。

## 结构与触发

三个目录均位于仓库根目录，作为可独立安装的 Skill 目录。每个目录仅包含必需的 `SKILL.md` 和 `agents/openai.yaml`；分析和主题阅读若需要较长的阶段清单，可分别使用本 Skill 的 `references/`，不建立共享运行时、脚本或外部依赖。

保持自动发现，但以窄描述避免误触发：检视阅读面向阅读决策，分析阅读面向具体材料理解，主题阅读面向多材料问题比较。普通推荐、泛书评或仅有书名且未要求阅读工作流时不触发。

## 失败与降级

- 材料不可读、章节缺失或来源不稳定：说明覆盖范围和受影响结论，不能补造内容。
- 只有标题或简介：转为阅读前计划，不给出原书分析结论。
- 主题阅读缺少问题：暂停并询问问题；材料不足两份：说明无法形成比较。
- 需要外部资料：先说明原书内在阅读已无法回答什么；仅在用户授权后检索，并将外部资料单列。
- 保存请求发生文件名冲突：比较、创建新版本或请求选择，绝不静默覆盖。

## 验证策略

先编写可复现的场景验收契约，再编写 Skill 指令。契约至少覆盖：

1. 检视阅读能基于目录、关键章节和结尾给出范围受限的阅读决策，而不冒充精读。
2. 分析阅读能区分知识类与文学类，并对知识类输出结构、术语、主张、论证和未解问题的证据定位。
3. 评议请求不会跳过理解重构，且不会把 AI 推断写成原文事实。
4. 主题阅读能以用户问题建立中立词汇和争议，而不是按某一本书的目录拼贴摘要。
5. 缺少原文、缺少主题问题、材料不足两份等场景会正确降级或暂停。
6. 每个 Skill 都通过结构校验、独立场景检查与真实授权材料的人工结果复核。

真实材料仅使用用户明确授权并且导出工具已报告 `validation.valid=true` 的结果。验收集包括《如何阅读一本书》、Book ID `552323d0813abbc5cg01570e`，以及用户提供的另外四本 Book ID `eb332820813ab9c71g011e20`、`bbc32a50813ab7953g01522a`、`0bf32020813ab7e6bg016510`、`42432e707190d338424666e`。完成导出后记录它们的真实标题、章节数、字符数、图片数与分配的验收场景。若缺少文学类授权材料，文学分流只做结构与指令审查，并在交付中明确该限制。

## 交付与发布

实现后，先在独立工作区中完成场景测试、结构校验和人工复核；仅在全部通过时提交三个根目录并推送到 `TianLanhe/read-skills`。不把用户的导出正文、认证状态、图片或测试材料提交进仓库。
